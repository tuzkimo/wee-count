# AI 记账助手 · 实机测试操作指引

> 这份指引假设你**不看代码**，也不需要懂技术。每一步都写清楚两件事：
> **你要做什么** 和 **你应该看到什么**。看到的不一样，就照第七节报给我们。
>
> 覆盖范围：AI 助手的**全部功能** —— 用大白话问账本、条件筛选、生成记账草稿、金额打码、
> 隐私开关、生成中取消、以及**截图记账**。

---

## 一、先准备三样东西

1. **一台 Android 手机**（Android 8 以上；平板也行）
2. **一根数据线**，并在手机上打开 USB 调试：
   设置 → 关于手机 → 连点 7 次「版本号」→ 返回 → 开发者选项 → 打开「USB 调试」
3. **在电脑上把后端跑起来，并配好 AI**（就是 `backend` 目录里那套 docker compose）

   **a. 先准备一份配置**

   - 进入 `backend` 目录，把配置样例复制成正式配置：
     - Windows：`copy .env.example .env`
     - macOS / Linux：`cp .env.example .env`
   - 用记事本打开 `backend\.env`，**有三处不改会直接起不来**（配置里写死了"必须设置"）：
     - `POSTGRES_PASSWORD=change-me` → 换成你自己随便定的密码
     - `REDIS_PASSWORD=change-me` → 同上
     - `JWT_SECRET` → 若为空，填一串随机字符
   - 再把 **AI 那三行**填好（其余 `AI_MAX_TOKENS` / `AI_TIMEOUT` / `AI_RATE_LIMIT` / `AI_DAILY_LIMIT` 保持默认）：

     | 配置项 | 怎么填 |
     |---|---|
     | `AI_API_KEY=` | **填上服务密钥**。⚠️ 这一行是**唯一开关**：留空 = 整个 AI 功能关闭，下面两行填了也无效 |
     | `AI_BASE_URL=https://api.deepseek.com/v1` | 用哪家就填哪家的地址，任何 **OpenAI 兼容**的服务都可以 |
     | `AI_MODEL=deepseek-chat` | ⚠️ **必须换成"能看图"的模型**。默认这个不一定支持图片，不改的话截图记账必然失败 |

   **b. 启动**

   ```
   cd backend
   docker compose up -d
   ```

   - 第一次会拉镜像，等几分钟
   - 确认三个服务都起来了：`docker compose ps`（`api` 那一行应为 running / healthy）
   - 后端地址就是 `http://localhost:8080/api/v1`
   - 想看日志：`docker compose logs -f api`（按 Ctrl+C 只是不看日志，容器还在跑）
   - 停止：`docker compose down`（数据保留）；连数据一起清掉：`docker compose down -v`

   **c. 让 App 连上这个后端**

   - **电脑上跑桌面版**（`npm run tauri dev`）：在 App 的「**服务器地址**」里填 `http://localhost:8080/api/v1`
   - **手机上**：⚠️ **不能填 `localhost`**（那指的是手机自己），要填**电脑的局域网地址**，
     例如 `http://192.168.1.23:8080/api/v1`。同时满足两点：手机和电脑连**同一个 Wi-Fi**；
     Windows 防火墙弹窗时选「允许访问」。
     （查电脑地址：Windows 用 `ipconfig`，macOS / Linux 用 `ifconfig` 或 `ip addr`，找 `192.168.x.x` 这种）
   - 如果 App 里一直提示「AI 服务暂时不可用」，按这个顺序查：
     ① 后端起来了吗（`docker compose ps`）② 地址填对了吗（尤其手机是不是填了 localhost）
     ③ `AI_MODEL` 是不是支持看图的模型 ④ `AI_API_KEY` 是不是空的

> ⚠️ `backend/.env` 只在你本机用，**不要提交到 git**。仓库里只有 `.env.example`（样例），
> 照着它复制一份即可 —— **不要直接改 `.env.example` 本身**。

**只想先在电脑上试试**（不用手机）：桌面版跑 `npm run tauri dev`，下面每一步操作完全一样。

### 3.5 真机排查补充：连后端前必须核对的三件事

**① 必须先登录/注册并绑定服务器，否则 AI 用不了。**

1. 进「绑定同步」页（路由 `/bind-sync`，入口在「我的」里找"绑定/同步"这类字样）
2. 「服务器地址」填 `http://<电脑IP>:8080/api/v1`（⚠️ 结尾的 `/api/v1` 必须有）
3. 点「注册」（在那台服务器上建个账号）或「登录」，再点「注册并同步」/「登录并同步」
4. 回到「我的」页，昵称下面应显示刚填的服务器地址 —— 显示不出来说明没进入在线态

> ⚠️ 为什么必须做这一步：AI 能力查询接口需要登录态。用手机浏览器直接打开
> `http://<电脑IP>:8080/api/v1/ai/status` 会返回 `{"error": "missing or invalid Authorization header"}`，
> 这是**正常现象**（地址栏访问不带登录令牌），说明服务器是通的。App 里登录后才会带上令牌。

**② 后端 CORS 白名单（桌面测在线模式时常需要；安卓实机一般不用改）**

- **安卓实机**：Tauri 壳发出的请求，Origin 是 `http://tauri.localhost`，它在白名单里
  ⇒ **安卓实机测试一般不会遇到跨域问题**。（这也是本项目以安卓实机为主测平台的原因之一。）
- **桌面开发**：`npm run tauri dev` 走 Vite 开发服务器，Origin 是 `http://localhost:1420`。
  Go 侧默认白名单包含它，但 **compose 文件里的回落值只有 `http://tauri.localhost` 一条** ——
  所以桌面测在线模式时要在 `backend/.env` 里显式写全两条：

```
CORS_ALLOWED_ORIGINS=http://tauri.localhost,http://localhost:1420
```

- 只有来源**不在上面两条里**时才需要换/加；来源可以从浏览器报错里原文照抄（报错会写 `Origin http://... has been blocked by CORS policy`）
- ⚠️ 这个变量**设置了就整体替换默认值，不是追加** —— 所以要连默认的两条一起写上
- 改完必须 `docker compose up -d` 重建容器；`docker compose restart` **不会**把新环境变量带进去

**③ 安卓端怎么看 console（排查用）**

- 首选：电脑 Chrome 打开 `chrome://inspect`，手机开着 USB 调试、App 处于运行状态 ⇒ 列表里出现 `Remote Target` ⇒ 点 inspect ⇒ 得到手机 WebView 的完整开发者工具（Console / Network）
- 备选：`adb logcat -c`，操作 App，再 `adb logcat -d | Select-String "chromium|CORS|status"`（WebView 的 console 输出带 `chromium` 标签）
- ⚠️ 刷新页面或重进 AI 页**不会**重新探测 AI 能力（客户端只在启动时探一次）⇒ 想抓启动那一刻的请求，要先打开 devtools 再重启应用

## 二、把 App 装到手机上（4 步）

1. 电脑上打开终端（Windows 用 PowerShell），进入项目目录
2. 输入并回车：

   ```
   npm run tauri android dev
   ```

   ⏳ 第一次编译要几分钟，终端会刷一大堆字，**这是正常的**。
3. 手机上会弹出安装提示 → 允许 → 桌面出现名为「**一起数钱**」的 App
4. **电脑终端不要关**（关掉 App 就断开连不上了）

## 三、先弄明白：这个助手能干什么

进去之后是**聊天界面**。它一共能做这几件事（下面四~五节就按这几件事逐条测）：

| 能力 | 一句话说明 |
|---|---|
| **问答** | 用大白话问钱的事，比如「上月买菜花了多少」 |
| **条件筛选** | 问得细一点也行，比如「上个月超过 100 的餐饮」；它会把条件显示成一个个标签，方便你核对 |
| **生成记账草稿** | 直接说「帮我记一笔：昨天晚饭 88，用微信」⇒ 它给一张**草稿卡**，你确认才真入账 |
| **截图记账** | 发一张账单/付款截图 ⇒ 它读金额分类，同样给草稿卡（M4 新功能） |
| **金额打码** | 回答里的金额**默认是打码的**，需要时你自己点开看 |
| **隐私开关** | 有一个"愿不愿意用 AI"的总开关；关着时输入框和按钮都点不动 |
| **随时取消** | 它正在"想"的时候，发送键会变成取消键，可以中断 |

> 💡 关键一点：**你的账本数据不上传**。它是在**手机本地**查库的，
> 只有查出来的**汇总数字**会发给模型 —— 这也是为什么金额默认打码。

## 四、正常流程测试

### A. 纯问答（5 步）

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 点底部进 **AI / 记账助手** 页面 | 聊天界面；输入框有灰字「问点什么，比如「上月买菜花了多少」」 |
| 2 | 确认那个"愿不愿意用 AI"的开关是**打开**的 | 关着的话输入框是灰的、点不动 |
| 3 | 输入：`上月买菜花了多少`，点「发送」 | 你的消息出现在上面；下面出现它在"想"的提示 |
| 4 | 等几秒 | 一段回答，里面有金额 —— **金额应该是打码的**（不是真实数字） |
| 5 | 点开打码处 / 找显示的入口 | 金额显示出来 |

### B. 条件筛选（4 步）

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 输入：`上个月超过 100 的餐饮` | |
| 2 | 点「发送」 | 回答上方/下方出现**条件标签**（比如"上个月"">100""餐饮"） |
| 3 | 核对标签是不是你问的意思 | 标签应与你问的一致 |
| 4 | 故意问一个含义不清的：`最近那些` | 它应该**反问你**或说明"不清楚"，而不是瞎猜一个结果 |

### C. 生成记账草稿（8 步）—— 这是最核心的功能

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 输入：`帮我记一笔：昨天晚饭 88，用微信` | |
| 2 | 点「发送」，等几秒 | 出现一张**草稿卡**：金额 88、分类（餐饮）、账户（微信） |
| 3 | 看卡片上的金额/分类 | **这里显示的是真实数字**（草稿卡是给你确认用的，不是给模型的回答） |
| 4 | 把金额改成 `98`（内联编辑） | 卡片上变成 98，**没有**立刻入账 |
| 5 | 点「确认」 | 卡片变成已确认状态；去账单/明细页，应能查到这笔 **98** 的支出 |
| 6 | 再说一句：`帮我记一笔：今天午饭 30`，出现草稿卡后点「撤销」 | 卡片消失；去明细页，**查不到**这 30 的支出 |
| 7 | **把 App 完全关掉再打开**，回到助手页面 | 已确认/已撤销的草稿**不会再冒出来** |
| 8 | 再看一眼第 6 步那条消息 | 撤销过的草稿卡应保持撤销后的样子 |

### D. 截图记账（8 步）

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 点输入框附近的**图片按钮**（悬停显示「选一张截图记账」） | 弹出手机自带的选图界面 |
| 2 | 选一张账单 / 付款成功页 / 小票截图 | 回到 App，输入框上方出现**缩略图** + 一行提示「截图会整张发给模型，可能含余额等其他信息」 |
| 3 | （可选）写一句话，比如「帮我记一下」 | **不写也能发** |
| 4 | 点「发送」 | 缩略图消失；你的消息在上方（带一张小图） |
| 5 | 等几秒 | 若认出了金额 ⇒ 出现**草稿卡**（同 C 节，确认才入账） |
| 6 | 选图后**切到别的页面再切回来** | 缩略图**还在**（这是这版特意修的） |
| 7 | 点缩略图上的「✕」 | 图消失，可以重新选 |
| 8 | 先选好图，再把"愿不愿意用 AI"的开关**关掉** | 缩略图**还在**，但「发送」和图片按钮都变灰点不动；开关打开后又能发 |

### E. 生成中取消（3 步）

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 问一个比较费时的问题（比如`把这半年的账都总结一下`） | 发送键**变成取消键** |
| 2 | 趁它还在"想"的时候点取消 | 这一轮停止；界面恢复到可以继续输入的状态 |
| 3 | 再正常问一句简单的 | 能正常回答（取消不会把助手弄坏） |

## 五、故意出错测试（这部分最重要，请逐条走一遍）

| # | 你这样操作 | 应该看到 | 说明 |
|---|---|---|---|
| 1 | 选一个 **PDF** 文件 | 「只支持 JPEG / PNG / WebP 图片」 | 非图片必须被拦住 |
| 2 | 选一个 **GIF 动图**（或用文件管理器把 .gif 改名成 .jpg 再选） | 「只支持 JPEG / PNG / WebP 图片」 | 改名骗不过去：它认**文件内容**，不认后缀 |
| 3 | 选一张**特别大**的照片（如 8MB 原图） | 大多数能成功（会自动压小）；压完还超 1MB 才提示「图片太大，换一张或先裁剪」 | **大 ≠ 失败**，别把成功当 bug |
| 4 | 选图界面点「取消」 | 什么都不发生（上一轮的失败提示会被清掉） | |
| 5 | 选图后**切页面再回来** | 缩略图还在 | |
| 6 | 选图后把 AI 开关关掉 | 图还在，但发送/选图都点不动 | 关开关 ≠ 删掉你选的图 |
| 7 | 让后端 `AI_MODEL` 换成**不支持图片**的模型，再发一张图 | 「这条没发出去：若带了截图，可能是当前模型不支持图片，试试先用文字描述。」 | 注意这句的前提措辞，它不武断 |
| 8 | 断网后发送 | 出现失败提示（可能是「AI 服务暂时不可用，请稍后重试。」） | |
| 9 | 连点两次「发送」 | 只有**一条**你的消息，不重复 | |
| 10 | 问一个账本里根本没有的东西（比如`我买过游艇吗`） | 它应该如实说没有相关记录，**不要**编一个数字 | 这是最重要的一条：不能编 |
| 11 | 问一个跟记账无关的（比如`今天天气怎么样`） | 它应该把话题拉回记账，而不是当通用聊天用 | |
| 12 | 把 `AI_API_KEY` 清空后重启后端，再问一句 | 会失败（AI 功能整体关闭）—— 这是**预期行为**，不是 bug | 测完记得填回去 |
| 13 | 连着快速问很多句（超过限流） | 会提示稍后再试 | 后端有速率与每日上限 |

## 六、隐私自查（1 分钟）

- **发图前**：那行「截图会整张发给模型，可能含余额等其他信息」的提示**必须存在**
- **发图后**：点开你发的那条消息，**缩略图还在** ⇒ 原图只在你手机本地
- **金额打码**：回答里的金额默认是打码的；把 App 关掉重开，**打码状态会恢复**
- **关掉手机网络**，再走一遍"选图 → 压缩 → 预览" ⇒ 这三步**不需要联网**，应该全程正常；
  只有点「发送」拿模型回答时才需要网络
- **问账本的问题**：条件筛选是**本地**查库的 ⇒ 关掉网络后问一句，应该会失败在"拿回答"这一步，
  而不是"查不到你的账"

## 七、出问题了怎么报（照抄这 6 条）

1. 手机型号 + Android 版本
2. 你发的图 / 你问的原话（图可以先打码）
3. 出错时的屏幕截图或录屏
4. **完整的错误文字**（一字不差照抄屏幕上的提示）
5. 电脑终端的**最后 30 行**输出。
   Android 还可以另开终端跑：`adb logcat -d > logcat.txt`，把这个文件发来
6. 后端用的 `AI_MODEL` 是什么

> 🔒 **不要**把 `AI_API_KEY` 发给任何人，包括我们。
> 💡 想让我们复现得最快，请把「你问的原话 + AI 的回答截图 + 错误文字」一起发来。

## 八、已知边界（出现了也**不算 bug**）

1. **动态图**（动画 WebP / APNG）会被当成静态图，只取**第一帧**。
   现在的判断只看文件开头的"魔数"，而动态图与静态图的开头**完全一样**，所以拦不住。
2. 如果服务商把回答换成了我们不认识的格式 ⇒ 会显示「AI 服务暂时不可用，请稍后重试。」。
   这是**故意的**：宁可明确告诉你"出错了"，也不假装成功给你一条**空回答**。
3. 选了一个**特别大的非图片文件**（比如几百 MB 的视频）⇒ 可能先卡顿一下再拒绝。
   现在的实现会先把文件整个读进内存才判断类型，这是已知的、还没修的小毛病。
4. **AI 会答错**：它是靠"看懂你的话 + 本地查库"来回答的，问法太绕时可能查偏。
   这类问题请**照第七节报给我们**（附上你的原话和它的回答），这属于我们要看的重点。
