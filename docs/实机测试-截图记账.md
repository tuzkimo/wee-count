# AI 记账助手 · 实机测试操作指引

> 这份指引假设你**不看代码**，也不需要懂技术。每一步都写清楚两件事：
> **你要做什么** 和 **你应该看到什么**。看到的不一样，就照第七节报给我们。
>
> 覆盖范围：AI 助手的**全部功能** —— 用大白话问账本、条件筛选、生成记账草稿、金额打码、
> 隐私开关、生成中取消、以及**截图记账**。

---

## 一、先准备三样东西

1. **一台 Android 手机**（Android 8 以上；平板也行）
2. **一根数据线**，并在手机上打开 USB 调试：
   设置 → 关于手机 → 连点 7 次「版本号」→ 返回 → 开发者选项 → 打开「USB 调试」
3. **在电脑上把后端跑起来，并配好 AI**（就是 `backend` 目录里那套 docker compose）

   **a. 先准备一份配置**

   - 进入 `backend` 目录，把配置样例复制成正式配置：
     - Windows：`copy .env.example .env`
     - macOS / Linux：`cp .env.example .env`
   - 用记事本打开 `backend\.env`，**有三处不改会直接起不来**（配置里写死了"必须设置"）：
     - `POSTGRES_PASSWORD=change-me` → 换成你自己随便定的密码
     - `REDIS_PASSWORD=change-me` → 同上
     - `JWT_SECRET` → 若为空，填一串随机字符
   - 再把 **AI 那三行**填好（其余 `AI_MAX_TOKENS` / `AI_TIMEOUT` / `AI_RATE_LIMIT` / `AI_DAILY_LIMIT` 保持默认）：

     | 配置项 | 怎么填 |
     |---|---|
     | `AI_API_KEY=` | **填上服务密钥**。⚠️ 这一行是**唯一开关**：留空 = 整个 AI 功能关闭，下面两行填了也无效 |
     | `AI_BASE_URL=https://api.deepseek.com/v1` | 用哪家就填哪家的地址，任何 **OpenAI 兼容**的服务都可以 |
     | `AI_MODEL=deepseek-chat` | ⚠️ **必须换成"能看图"的模型**。默认这个不一定支持图片，不改的话截图记账必然失败 |

   **b. 启动**

   ```
   cd backend
   docker compose up -d
   ```

   - 第一次会拉镜像，等几分钟
   - 确认三个服务都起来了：`docker compose ps`（`api` 那一行应为 running / healthy）
   - 后端地址就是 `http://localhost:8080/api/v1`
   - 想看日志：`docker compose logs -f api`（按 Ctrl+C 只是不看日志，容器还在跑）
   - 停止：`docker compose down`（数据保留）；连数据一起清掉：`docker compose down -v`

   **c. 让 App 连上这个后端**

   - **电脑上跑桌面版**（`npm run tauri dev`）：在 App 的「**服务器地址**」里填 `http://localhost:8080/api/v1`
   - **手机上**：⚠️ **不能填 `localhost`**（那指的是手机自己），要填**电脑的局域网地址**，
     例如 `http://192.168.1.23:8080/api/v1`。同时满足两点：手机和电脑连**同一个 Wi-Fi**；
     Windows 防火墙弹窗时选「允许访问」。
     （查电脑地址：Windows 用 `ipconfig`，macOS / Linux 用 `ifconfig` 或 `ip addr`，找 `192.168.x.x` 这种）
   - 如果 App 里一直提示「AI 服务暂时不可用」，按这个顺序查：
     ① 后端起来了吗（`docker compose ps`）② 地址填对了吗（尤其手机是不是填了 localhost）
     ③ `AI_MODEL` 是不是支持看图的模型 ④ `AI_API_KEY` 是不是空的

> ⚠️ `backend/.env` 只在你本机用，**不要提交到 git**。仓库里只有 `.env.example`（样例），
> 照着它复制一份即可 —— **不要直接改 `.env.example` 本身**。

**只想先在电脑上试试**（不用手机）：桌面版跑 `npm run tauri dev`，下面每一步操作完全一样。

### 3.5 真机排查补充：连后端前必须核对的三件事

**① 必须先登录/注册并绑定服务器，否则 AI 用不了。**

1. 进「绑定同步」页（路由 `/bind-sync`，入口在「我的」里找"绑定/同步"这类字样）
2. 「服务器地址」填 `http://<电脑IP>:8080/api/v1`（⚠️ 结尾的 `/api/v1` 必须有）
3. 点「注册」（在那台服务器上建个账号）或「登录」，再点「注册并同步」/「登录并同步」
4. 回到「我的」页，昵称下面应显示刚填的服务器地址 —— 显示不出来说明没进入在线态

> ⚠️ 为什么必须做这一步：AI 能力查询接口需要登录态。用手机浏览器直接打开
> `http://<电脑IP>:8080/api/v1/ai/status` 会返回 `{"error": "missing or invalid Authorization header"}`，
> 这是**正常现象**（地址栏访问不带登录令牌），说明服务器是通的。App 里登录后才会带上令牌。

**② 后端 CORS 白名单（桌面测在线模式时常需要；安卓实机一般不用改）**

- **安卓实机**：Tauri 壳发出的请求，Origin 是 `http://tauri.localhost`，它在白名单里
  ⇒ **安卓实机测试一般不会遇到跨域问题**。（这也是本项目以安卓实机为主测平台的原因之一。）
- **桌面开发**：`npm run tauri dev` 走 Vite 开发服务器，Origin 是 `http://localhost:1420`。
  Go 侧默认白名单包含它，但 **compose 文件里的回落值只有 `http://tauri.localhost` 一条** ——
  所以桌面测在线模式时要在 `backend/.env` 里显式写全两条：

```
CORS_ALLOWED_ORIGINS=http://tauri.localhost,http://localhost:1420
```

- 只有来源**不在上面两条里**时才需要换/加；来源可以从浏览器报错里原文照抄（报错会写 `Origin http://... has been blocked by CORS policy`）
- ⚠️ 这个变量**设置了就整体替换默认值，不是追加** —— 所以要连默认的两条一起写上
- 改完必须 `docker compose up -d` 重建容器；`docker compose restart` **不会**把新环境变量带进去

**③ 安卓端怎么看 console（排查用）**

- 首选：电脑 Chrome 打开 `chrome://inspect`，手机开着 USB 调试、App 处于运行状态 ⇒ 列表里出现 `Remote Target` ⇒ 点 inspect ⇒ 得到手机 WebView 的完整开发者工具（Console / Network）
- 备选：`adb logcat -c`，操作 App，再 `adb logcat -d | Select-String "chromium|CORS|status"`（WebView 的 console 输出带 `chromium` 标签）
- ⚠️ 刷新页面或重进 AI 页**不会**重新探测 AI 能力（客户端只在启动时探一次）⇒ 想抓启动那一刻的请求，要先打开 devtools 再重启应用

## 二、把 App 装到手机上（4 步）

1. 电脑上打开终端（Windows 用 PowerShell），进入项目目录
2. 输入并回车：

   ```
   npm run tauri android dev
   ```

   ⏳ 第一次编译要几分钟，终端会刷一大堆字，**这是正常的**。
3. 手机上会弹出安装提示 → 允许 → 桌面出现名为「**一起数钱**」的 App
4. **电脑终端不要关**（关掉 App 就断开连不上了）

## 三、先弄明白：这个助手能干什么

进去之后是**聊天界面**。它一共能做这几件事（下面四~五节就按这几件事逐条测）：

| 能力 | 一句话说明 |
|---|---|
| **问答** | 用大白话问钱的事，比如「上月买菜花了多少」 |
| **条件筛选** | 问得细一点也行，比如「上个月超过 100 的餐饮」；它会把条件显示成一个个标签，方便你核对 |
| **生成记账草稿** | 直接说「帮我记一笔：昨天晚饭 88，用微信」⇒ 它给一张**草稿卡**（卡上只读，改不了），你点「确认记账」才真入账 |
| **截图记账** | 发一张账单/付款截图 ⇒ 它读金额分类，同样给草稿卡（M4 新功能） |
| **金额打码** | 回答里的金额**默认是打码的**，需要时你自己点开看 |
| **隐私开关** | 有一个"愿不愿意用 AI"的总开关；关着时输入框和按钮都点不动 |
| **随时取消** | 它正在"想"的时候，发送键会变成取消键，可以中断 |

> 💡 关键一点：**你的账本数据不上传**。它是在**手机本地**查库的，
> 只有查出来的**汇总数字**会发给模型 —— 这也是为什么金额默认打码。

## 四、正常流程测试

### A. 纯问答（5 步）

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 点底部进 **AI / 记账助手** 页面 | 聊天界面；输入框有灰字「问点什么，比如「上月买菜花了多少」」 |
| 2 | 确认那个"愿不愿意用 AI"的开关是**打开**的 | 关着的话输入框是灰的、点不动 |
| 3 | 输入：`上月买菜花了多少`，点「发送」 | 你的消息出现在上面；下面出现它在"想"的提示 |
| 4 | 等几秒 | 一段回答，里面有金额 —— **金额应该是打码的**（不是真实数字） |
| 5 | 点开打码处 / 找显示的入口 | 金额显示出来 |

### B. 条件筛选（4 步）

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 输入：`上个月超过 100 的餐饮` | |
| 2 | 点「发送」 | 回答上方/下方出现**条件标签**（比如"上个月"">100""餐饮"） |
| 3 | 核对标签是不是你问的意思 | 标签应与你问的一致 |
| 4 | 故意问一个含义不清的：`最近那些` | 它应该**反问你**或说明"不清楚"，而不是瞎猜一个结果 |

### C. 生成记账草稿（8 步）—— 这是最核心的功能

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 输入：`帮我记一笔：昨天晚饭 88，用微信` | |
| 2 | 点「发送」，等几秒 | 出现一张**草稿卡**：金额 88、分类（餐饮）、转出（微信）、日期 |
| 3 | 看卡片上的金额和字段 | 卡片金额**也受打码开关管**（默认打码，点页面右上角的眼睛图标可看真值）；分类/账户/日期/备注/标签一律**只读** |
| 4 | 想改金额或分类 | ⚠️ 卡上**改不了**（没有任何输入框，也没有「修改」按钮）：在对话里**重说一句**（比如`改成 98`）让它重新出一张卡；要精细改，等确认入账后去**流水列表**改那条流水 |
| 5 | 点「确认记账」 | 卡片变成「**已记账 ✓**」并多出一颗「撤销」；去账单/明细页，应能查到这笔 **88** 的支出 |
| 6 | 再说一句：`帮我记一笔：今天午饭 30`，出现草稿卡后点「**撤回**」 | ⚠️ 卡片**不会消失**，而是变成一张灰字「**已撤回**」的静态卡（卡上不再有任何按钮）；去明细页，**查不到**这 30 的支出 |
| 7 | **把 App 完全关掉再打开**，回到助手页面 | 第 5 步那张卡仍是「已记账 ✓ + 撤销」，第 6 步那张仍是「已撤回」—— 两个决定都记住了，不会变回待确认 |
| 8 | 点第 5 步那张卡上的「撤销」 | 撤销成功 ⇒ 卡片**退回待确认**、那笔 88 从明细页消失；可以再点「确认记账」重新入账 |

### D. 截图记账（8 步）

| 步骤 | 你要做什么 | 你应该看到什么 |
|---|---|---|
| 1 | 点输入框附近的**图片按钮**（悬停显示「选一张截图记账」） | 弹出手机自带的选图界面 |
| 2 | 选一张账单 / 付款成功页 / 小票截图 | 回到 App，输入框上方出现**缩略图** + 一行提示「截图会整张发给模型，可能含余额等其他信息」 |
| 3 | （可选）写一句话，比如「帮我记一下」 | **不写也能发** |
| 4 | 点「发送」 | 缩略图消失；你的消息在上方（带一张小图） |
| 5 | 等几秒 | 若认出了金额 ⇒ 出现**草稿卡**（同 C 节，确认才入账） |
| 6 | 选图后**切到别的页面再切回来** | 缩略图**还在**（这是这版特意修的） |
| 7 | 点缩略图上的「✕」 | 图消失，可以重新选 |
| 8 | 先选好图，再把"愿不愿意用 AI"的开关**关掉** | 缩略图**还在**，但「发送」和图片按钮都变灰点不动；开关打开后又能发 |

### D2. 分享记账（5 步）—— 截完图不用回 App 找相册

> 适用：你在**别的 App 里截了图**（支付宝/微信的付款页、账单列表、小票照片），
> 想直接送给助手，而不用切回 App 一张张翻相册。

1. 在任意 App 里截图（系统截图）→ 点截图浮窗里的「**分享**」
2. 系统分享面板里选「**一起数钱**」（没有的话见下面"看不到入口"）
3. App 打开。**如果你刚才只是切出去（从后台回来），而且没超过自动锁设定的时间，就不该再让你解锁**；
   只有"你自己在最近任务里把它划掉了"、或离开时间超过了自动锁窗口，才会先看到解锁页
4. 落到的就是 **AI 页**，输入框上方已经有那张图的缩略图 + 隐私提示
5. 想补一句话就补（比如"这张小票算餐饮"），不想补就直接点「发送」

**看不到「一起数钱」这个入口**：① 分享的对象不是**图片**（视频/PDF/链接不会出现本 App）；
② 极少数 App 的分享面板只列"常用"应用，点「更多」或「全部」找一下。

**一次分享多张**：只会用**第一张**，并在输入框上方提示「一次只能记一张，已用第一张」。

**分享进来之后我什么都不做就退出了**：那张图**不会**留在任何地方（App 私有缓存里的那份
已经删掉了）；系统相册里的原截图**不受影响**，要不要删它由你决定（系统截图浮窗自带删除）。

### D3. 分享进来时的解锁行为（A/B ①–⑥ + ⑦）

> 这一节专门核"什么时候该让你解锁、什么时候不该"。**六条都请照着做**；看到的不一样，
> 就按第七节那 6 条报给我们（每条下面都写了该报什么、要看哪一行日志）。
> 前提：你已经开了"应用锁"。设置里的自动锁只有 **立即 / 1 分钟 / 5 分钟** 三个选项。
>
> **通用准备**：手机连上电脑后先跑一次 `adb logcat -c` 清空日志；每次要看的日志用
> `adb logcat -v time -s WeeCount/Session WeeCount/Share`。**"直接看盘"比任何推断都有效**
> （需要 debug 版 App —— 就是 `tauri android dev` 装的那一版）：
> `adb shell run-as cn.tuzkimo.wee_count ls -l cache/wee-session` 与
> `adb shell run-as cn.tuzkimo.wee_count cat cache/wee-session/session.json`。

**① 从最近任务里划掉「一起数钱」，再点图标打开 ⇒ 必须要求解锁（硬要求）**

- **怎么做**：先在 App 里解锁进到正常页面 → 按"最近任务"键（方形按钮 / 手势上滑并停住）→
  把「一起数钱」那张卡片**划掉** → 再点桌面图标打开 App
- **应该看到**：**解锁页**（你自己关掉了它，所以要重新解锁）；解锁后回到刚才的页面。
  ⚠️ 请**再重复一遍**"解锁 → 从最近任务划掉 → 再点图标打开"：**每一次都必须要求解锁**
  （不能只有第一次锁、后面就不锁了）
- **要看的日志**：**必须**出现这样一行
  `task 变了（记录=1234 当前=5678）⇒ 改判 user_closed`（数字是你的任务号，不一定和这里一样）
  —— 这一行就是"App 认出了你是自己划掉的"的证据。再顺手看盘：
  `ls -l cache/wee-session` 应当**只列出 `session.json`**（那个叫 `authenticated` 的标记
  应当已经被删掉）；`cat session.json` 应当同时含 `"taskId"` 与 `"authenticated"` 两个字段，
  且 `"reason"` 是 `"user_closed"`
- **不符合就报**：**直接进了业务页、没要求解锁** ⇒ 这是要紧的问题，请立刻按第七节报，
  并写清手机型号 + 自动锁选项 + 是不是开了应用锁。再附上
  `adb logcat -d -s WeeCount/Session > session-log.txt` ——
  ⚠️ 如果日志里**一条 `task 变了` 都没有**，请特别说明：那说明你这台手机的"划掉后台"
  没有换任务号（我们要据此改判据）
- **说明**：点"清除全部"清掉最近任务也算同一件事；只是按 Home 键或切到别的 App **不算**

**② 切到后台停 10 秒就回来、或期间分享一张图 ⇒ 不该要求解锁（Bug ① 不能回退）**

- **怎么做**：在 App 里**解锁一次**、进到正常页面 → 按 Home 键或切到别的 App，**停约 10 秒**
  （⚠️ 不要划掉）→ 直接点图标回来；再单独做一次"停 10 秒 → 在别的 App 里截图 → 分享进来"
- **应该看到**：**直接回到原页面 / 直接落在 AI 页**（图已附上），**没有解锁页**。
  （自动锁设成「立即」时例外 —— 那种设置下要求解锁是对的）
- **要看的日志**：应是 `离开前台 ⇒ 写 background（authenticated=true）`，且**没有** `task 变了` 那一行
- **不符合就报**：看到解锁页、或日志里出现了 `task 变了` ⇒ 按第七节报，写清 ①自动锁选项
  ②从切出去到回来大约多少秒 ③手机型号
- **说明**：App 被系统在后台杀掉、页面重新加载（手机内存紧张时会发生）都算"还在窗口内"，
  同样**不该**要求解锁

**③ 停在解锁页不输口令 → 切后台 → 被系统杀掉 → 1 分钟内点回 ⇒ 必须仍停在解锁页**

- **怎么做**：冷启动 App，**停在解锁页、不要输口令** → 按 Home → 在电脑上跑
  `adb shell am kill cn.tuzkimo.wee_count`（杀后台进程，**不动**最近任务里的卡片）→
  1 分钟内点图标回到 App
- **应该看到**：**仍然是解锁页**（没输过口令，就不该因为"时间还短"放你进去）
- **要看的日志**：应是 `离开前台 ⇒ 写 background（authenticated=false）`

## 八、已知边界（出现了也**不算 bug**）

1. **动态图**（动画 WebP / APNG）会被当成静态图，只取**第一帧**。
   现在的判断只看文件开头的"魔数"，而动态图与静态图的开头**完全一样**，所以拦不住。
2. 如果服务商把回答换成了我们不认识的格式 ⇒ 会显示「AI 服务暂时不可用，请稍后重试。」。
   这是**故意的**：宁可明确告诉你"出错了"，也不假装成功给你一条**空回答**。
3. 选了一个**特别大的非图片文件**（比如几百 MB 的视频）⇒ 可能先卡顿一下再拒绝。
   现在的实现会先把文件整个读进内存才判断类型，这是已知的、还没修的小毛病。
4. **AI 会答错**：它是靠"看懂你的话 + 本地查库"来回答的，问法太绕时可能查偏。
   这类问题请**照第七节报给我们**（附上你的原话和它的回答），这属于我们要看的重点。
5. 连着说两句「帮我记一笔」：前一张**还没确认**的草稿卡会**直接从界面上消失**（被新草稿取代），
   这是有意为之 —— 同一时刻只留一张待确认卡。**已经点过「确认记账」或「撤回」的卡不受影响**，
   它们照旧留在原位。
6. **你删掉相册里的截图，聊天记录里那份还在。** 助手把图**整张**收下后会在本地会话里存一份
   缩略图（**历史对话里**那份是打码显示的），这是它"看得见历史"的前提。系统相册那份与它无关：
   删相册只是删系统那份。要把会话里那份也清掉，用 AI 页右上角的「**清空**」（那才是真删）。
7. **分享进来偶尔"没反应"**（图没附上、也没弹任何提示）。系统借给我们的图是先由 App 在
   **后台**拷进来的，云端相册里（存在云端的）照片可能几秒才拷完；而 App 只在你每次
   "回到前台"时去取，取空后会**再补一次**（约 1.2 秒后）。拷贝比这还慢时这一次就会错过 ——
   **切出去再切回来**（去别的 App 再回来）就会接住。这是有意接受的取舍：宁可偶尔晚一拍，
   也不让 App 冷启动时卡成白屏。
8. **手动清理 App 缓存（或系统自动清缓存）之后，第一次打开会要求你解锁一次。**
   App 在自己的缓存目录里放了两个小文件，用来记住"上次是你自己划掉的、还是只是切到了后台"
   和"这一段你解锁过了"。缓存被清掉后它就读不到了，于是**从严**处理：要求解锁一次。
   解锁过之后一切照常 —— 这不是 bug。
9. **「强行停止」之后重新打开、以及手机重启后打开，会不会要求解锁 —— 这一条待你确认。**
   系统"强行停止"**不通知** App（连"我离开了前台"都来不及记），App 记着的还是更早那一次；
   现在的设计是启动时比对"这一次还是不是同一个任务"，所以**强停后预期会要求解锁**。
   但**强行停止到底会不会把任务一起销毁，取决于你的手机 ROM**，我们自己判不了。
   **「重启」是另一回事：重启后任务号可能被复用**（系统里那个编号是内存态、重启后从头分配），
   一旦被复用就不会按"你自己关掉了"处理，而是回到时间窗口判断 ⇒ 所以**重启后 5 分钟内
   打开，很可能不要求解锁**（在窗口内、且你刚解锁过，这是**合理**的；超出窗口仍然要解锁）。
   两种情形都请按 D3 ⑤ 把原始现象发回来（`cat cache/wee-session/session.json` 里的
   `taskId`/`reason` + 那段 `adb logcat -v time -s WeeCount/Session` + 这次要不要解锁）。
   **任何结果都不算 bug**，我们要的是你这台机器的实际表现。
10. **失败分享留下的半截图，最坏要等下一次成功分享才被清掉。** inbox 里的孤儿清理只在
    **成功分享**时跑一次（失败那次连"该留哪张"都没有）⇒ 偶尔看到 inbox 里多出一个 `.bin`
    是正常的，**不是**泄漏：下一次成功分享就会收口。只有当它"只增不减"时才需要报（D3 ⑥）。
11. **连着很快分享两次时，第二次要等下一次回到前台才被接上。** 第一次正在处理时若又来了
    一次分享，App 会**故意不动**盘上那份新记录（否则会把你刚分享的那次吞掉）⇒ 第二次的图
    不会立刻出现，等你**切出去再切回来**（或解锁后）那次拉取才处理。**不丢，但不即时** ——
    这是明确接受的取舍。
12. **输入框上方那张"待发图"的预览不会被模糊**（打码开着也是清晰的）。只有**历史对话里**的
    图（缩略图与全屏大图）才跟随打码开关。代价是：**别人看你屏幕时会看到这张刚分享进来的图**
    （它可能含余额）。这是我们**故意**这么做的 —— 否则每次截图记账都要先点一次眼睛才能确认
    图对不对，而眼睛是全局开关、点开会把历史消息一起揭掉，等于把"防偷看"变成"给自己添一步"。
    所以这一条**不算 bug**；如果你希望待发图也跟着模糊，请照第七节报，我们按新规格再评。
