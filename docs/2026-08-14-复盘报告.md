# WeeCount 项目复盘报告

> 日期：2026-08-14　范围：全项目（前端 Vue3+TS、Tauri 2.0 壳、Go 后端、安全与基础设施）
> 方式：4 路并行只读审计 + 关键结论源码复核，未改动任何文件。

---

## 总体判断

架构方向是对的——离线优先、LWW 增量同步、引用闭包补父行、全链路参数化 SQL、密钥未入 git，这些底子都在。但存在**两个成簇的高危问题区**：

1. **同步正确性**：一串「静默丢数据 / 污染数据 / 假已同步」的 bug。
2. **授权模型**：几处「登录即可越权读他人数据」的洞。

都不是设计层面的错，是执行层面的漏网，多数能定点修。以下按严重度分级，`文件:行号` 可直接跳转。

---

## 一、高危（建议优先处理）

### A. 同步正确性（丢数据 / 数据污染 / 假「已同步」）

1. **标签清空永远同步不上去（前后端双端断链）** — 最确定、用户可感知。
   - 前端 `src/stores/transaction.ts:314-322` 清空标签后，`assembleTransaction` 不设 `tag_ids`（`undefined`），序列化时字段丢失；后端 `backend/internal/service/sync.go:281` 又用 `len(t.TagIDs) > 0` 守卫，空切片直接跳过删旧标签。结果：清空标签 → 服务端旧标签保留 → 下次拉取旧标签「复活」。
   - 修法：前端无标签时显式传 `tag_ids: []`；后端把 `DELETE FROM transaction_tags` 移到 `len>0` 判断之外（无条件先删再插）。

2. **`performSync` 网络异常时丢队列 + 误报「已同步」** — `src/services/sync.ts:127-150`。
   - `pendingChanges` 在 128 行已清空，137 行 `await apiFetch` **无 try/catch**。`apiFetch`/`fetchWithTimeout` 断网/超时会直接 throw，于是 `mergeChanges` 回队（147 行）和 `markSyncResult(false)` 都不执行：本地变更从同步队列彻底丢失（DB 里还在，但除非再编辑否则永不补推），MePage 还显示绿点。离线优先 App 里网络异常恰恰是最常命中的路径。
   - 修法：给 `apiFetch` 调用包 try/catch（或让 `apiFetch` 内部 catch 网络错返回 `{ok:false,error}`），失败统一「回队 + 标记失败」。

3. **`lwwMergeCategory` 命中重复分类且本地更旧时确定性 500** — `backend/internal/service/sync.go:235`。
   - INSERT 分支找到同名同类型分类后，若 `c.UpdatedAt.After(dupUpdatedAt)` 为 false，`return err` 返回的是**外层 Scan 的非 nil 错误（`pgx.ErrNoRows`）**，导致整个同步 500、卡死。
   - 修法：该分支改 `return nil`（跳过），仅在实际执行 UPDATE 后返回 Exec 的 err。

4. **`remove`/`batchRemove` 推送「部分墓碑」，服务端把真实数据清零** — `src/stores/transaction.ts:361,390` + 后端 `sync.go:271-274`。
   - 删除时只传 `{ id, is_deleted:true, updated_at }`，Go 反序列化后 amount/type/occurred_at 等为零值，`lwwMergeTransaction` 整行 UPDATE 覆盖，线上流水变 amount=0、type 空串、`occurred_at` 归公元 0001 年。README 已承认账户/标签删除有同类问题并改为推完整对象，**流水侧漏改**。
   - 修法：删除前从 DB 取完整行再加 `is_deleted:true` 入队（与 account.ts 对齐）。

5. **`pendingChanges` 跨账号串数据** — `src/services/sync.ts:33-40` + `auth.ts` logout。
   - `pendingChanges`/`syncTimer` 是模块级变量，游标虽按 uid 隔离了「拉取」方向，但 logout/切用户时不清空队列。用户 A 离线积压的变更会在 B 登录后被当作 B 的 `local_changes` 推到 B 账号。
   - 修法：logout/unbind/切用户时清空队列并 `clearTimeout(syncTimer)`，或像 `cursorKey` 一样按 uid 隔离。

6. **增量游标推进竞态，可能静默丢数据** — `backend/internal/service/sync.go:41-43,299-356`。
   - `applyLocalChanges` 提交后 `getRemoteChanges` 用 `updated_at > since` 读，最后 `ServerTime = time.Now()`。另一客户端若在「读完成」与「取 ServerTime」之间提交了 `updated_at < ServerTime` 的写，本次读不到、下次 `since=ServerTime` 又跳过 → 永久丢失。`getRemoteChanges` 不在一致快照事务内。
   - 修法：读 + 游标推进放进单个 REPEATABLE READ 事务，用事务快照时间作为 `next_cursor` 显式返回。

7. **`applyRemoteChanges` 标签重建违反 LWW** — `src/services/sync.ts:292-300`。
   - `if (tx.tag_ids)` 在 `else if (updated_at > local)` **之外**，无条件执行。远端流水较旧时交易行被正确跳过，但标签关联仍被远端旧值覆盖，本地更新的标签改动被静默回退。
   - 修法：把标签重建移入「新插入」和「`updated_at > local` 更新」两个分支内。

8. **6 个 `lwwMerge*` 都用 `err != nil` 误判「行不存在」** — `backend/internal/service/sync.go:151-297,622-643`。
   - 应 `errors.Is(err, pgx.ErrNoRows)` 判「不存在」，其余错误（连接失败、死锁、序列化失败）直接返回。当前会把真实 DB 故障误判为「未找到」去 INSERT，掩盖故障或制造令人困惑的 duplicate key 错。

### B. 安全 / 越权（已源码核实）

1. **`ListMembers` 越权（IDOR）** — `backend/internal/service/team.go:192-218`。
   - `ListMembers(ctx, teamID)` 不收 `userID`、不做成员校验，任意登录用户按 team_id 枚举任意团队的 username/nickname/avatar/role。
   - 修法：入参加 `userID`，先验 `(team_id,user_id) ∈ team_members`。

2. **access token 可当 refresh token 无限续期** — `backend/internal/service/auth.go:189-232`。
   - `Refresh` 只验 HMAC + `sub`，无 `typ`/`token_type` 区分；refresh 无轮换/无服务端撤销，30 天泄露即永久会话。
   - 修法：签发时加 `"typ":"access"|"refresh"` 并在 Refresh 强制 `typ=="refresh"`，引入轮换/Redis 黑名单。

3. **Tauri CSP 为 null + 任意 SQL 权限** — `src-tauri/tauri.conf.json:20-22`（`"csp": null`）+ `src-tauri/capabilities/default.json:9-12`（`sql:allow-load/execute/select` 无 scope）。
   - 一旦出现 XSS，攻击脚本可在主窗口执行任意 SQL 直接读写本地库并外发账目。
   - 修法：配置严格 CSP，并把 SQL capability 收窄到最小白名单（这两个闸当前全开，要一起做）。

4. **docker-compose 弱默认密钥** — `backend/docker-compose.yml:9,21`。
   - `JWT_SECRET:-change-me-in-production`、`POSTGRES_PASSWORD:-wee` 已入库，`config.Load` 的必填校验被 compose 兜底值架空，忘记建 .env 就一键启动即用公开密钥运行。
   - 修法：改 `${JWT_SECRET:?必须设置}` 强制注入。

5. **`member_aliases` 无归属校验、全员广播** — `backend/internal/service/sync.go:142-146,645-664`。
   - 写入侧信任客户端 `setter_user_id`（可伪造），读取侧 `updated_at > since` 全局返回所有人的别名，任何 `/sync` 都能拉全站别名。
   - 修法：按 setter 隔离，服务端强制 `setter==当前用户`。

## 二、中危

- **TransactionList 事件监听未清理** `src/views/TransactionList.vue:177-179`：`document.addEventListener("click")` 无 `onUnmounted` 移除，每次进首页叠加监听器，闭包持有已卸载组件的 ref（内存泄漏 + 重复执行）。
- **全站无速率限制** `backend/cmd/server/main.go:56-58`：`/auth/login`、`/auth/register`、`/teams/join` 均可暴力破解；6 位数字邀请码（10^6 空间）可离线爆破入组。
- **refresh_token 明文存 localStorage** `src/services/api.ts:42,147`，且 logout 不清除（便于自动恢复）；设备 root 后可取走冒充用户。
- **同步失败后无自动重试** `src/services/sync.ts`：指数退避只在会话恢复路径，`performSync` 失败只回队不重新武装定时器，「断网编辑→恢复」不自动补推。
- **`updateProfile` 改昵称不刷新 ledger 内存缓存** `src/stores/auth.ts:285-308`：改名后账本名要等下次 `init()` 才更新。
- **`accountStore.remove` 不校验关联流水** `src/stores/account.ts:197-229`：软删账户后名下流水成孤儿，与 `categoryStore.remove` 的 COUNT 校验不一致。
- **LWW 时间戳用字符串字典序比较** `src/services/sync.ts:198` 等 + `src/services/migration.ts`：`"YYYY-MM-DD HH:MM:SS"`（空格）与 `"…T…Z"` 比较因 `" " < "T"` 恒判「更旧」，`firstFullSync` 未过 `toIsoTimestamp`，旧数据升级首同步可能 400。
- **错误回显泄露内部细节** `backend/internal/handler/team.go:59,88,99`、`backend/internal/handler/auth.go:119`：`err.Error()` 原样返回客户端（redis 连接串、pgx 内部错误等），且 403/400/500 状态码混用。
- **Docker 供应链** `backend/Dockerfile:4`（`GOSUMDB=off`）、以 root 运行、`docker-compose.yml` 把 Postgres/Redis 端口绑 `0.0.0.0` 且 Redis 无密码。
- **categories 缺 `(ledger_id, updated_at)` 复合索引** `backend/internal/service/sync.go:487-506` + 迁移 001；`team_members(user_id)`、`ledgers(team_id)` 也无索引，团队/账本多了全表扫。
- **`getMe` 漏查 `rows.Err()`** `backend/internal/service/auth.go:120-146`：迭代中途出错被静默吞掉返回截断结果。

## 三、值得重构的点（架构级，按优先级）

1. **同步模块收口：按 uid 隔离的队列 + 互斥 + 统一错误边界**。把 `pendingChanges`/`syncTimer` 从模块级改为按 uid 隔离，加 `isSyncing` 互斥（auth store 里已有 `isSyncing` ref 却从未用于 `performSync`），并把 `apiFetch`/`applyRemoteChanges`/`firstFullSync` 全部纳入单一 try/catch + 「回队 + 标记失败 + 退避重试」。一次性解决 A2/A5 + 中危「无自动重试」同根问题。

2. **后端 6 份 `lwwMerge*` 样板抽成 repository 层通用 merge**。它们高度重复且各自埋雷（`err != nil` 误判、category 的 `return err`、tag 清空失效）；统一成「按主键查 + `pgx.ErrNoRows` 判定 + 通用 merge 函数」能从根上消灭这一类 bug。

3. **统一授权原语 `canReadTeam`/`canReadLedger`，在每个 team/sync service 入口强制调用**。`ListMembers` IDOR、`member_aliases` 广播、ledger 归属字段可被覆写，三者同源于「service 方法不自带鉴权上下文」，收口到一处可系统解决。

4. **增量游标改为原子一致快照**（对应 A6）。`getRemoteChanges` 包进 REPEATABLE READ 事务、游标取快照时间、显式返回 `next_cursor`。

5. **补 DB 集成测试**（testcontainers/pgxmock）。现有测试全是纯函数 + httptest，`queryTransactions` 的 `uuid[]→[]string` 扫描、category 的 `return err`、tag 清空失效这些 bug 都没被网住。

6. **前端大组件拆分**：`TransactionList.vue`（706 行）、`RecordPage.vue`（610 行）职责过重，纯函数（格式化、取图标）抽到 utils，表单状态+校验抽成 `useTransactionForm` composable；顺带修复事件监听泄漏、转账 `from===to` 校验等。

7. **删除/墓碑统一推完整对象**：抽 `buildSyncTransaction(id)` 从 DB 取完整行，`remove`/`batchRemove` 复用，与 account/tag 修复对齐。

8. **时间戳统一为单一 ISO 表示**：LWW 比较、`firstFullSync` 出口、`toIsoTimestamp` 各自为政，统一归一化消除 `" " vs "T"` 字典序误判。

## 四、已核实为「非问题」的澄清（避免误修）

- **SQL 注入**：前后端全链路参数化（pgx `$1`/`ANY($1)`、plugin-sql `?`），无动态拼接注入面。
- **`?` 与 `$1` 占位符混用**：sqlx 驱动两种写法均有效，纯风格不一致。
- **外键约束**：SQLite `foreign_keys=ON` 默认开启，「引用闭包补父行」修复方向正确，后端 `collectReferencedIDs` 已覆盖 ledger/account/category/tag + 交易 `tag_ids` 五类。
- **CORS**：非通配符、精确匹配、`AllowCredentials:false`，无「通配符+凭证」隐患；算法混淆攻击面已封堵（固定 HMAC 并拒绝非 HMAC）。
- **密钥入 git**：`backend/.env` 未被追踪（`git ls-files` 确认），`.gitignore` 正确挡住。
