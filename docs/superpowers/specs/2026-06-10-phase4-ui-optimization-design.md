# Phase 4 — UI 优化方案

> 基于 Phase 3 完成内容，对页面布局、导航结构、交互体验进行重构优化。

## 一、路由重构

| 路径 | 页面 | Tab | 说明 |
|------|------|-----|------|
| `/` | TransactionList | 首页 | 流水页做首页，展示全部账户流水 |
| `/accounts/:id` | TransactionList | 账户 | 复用流水页，默认筛选当前账户 |
| `/record` | RecordPage | — | 记账新增 |
| `/record/:id` | RecordPage | — | 记账编辑 |
| `/filter` | FilterPage | — | 筛选页（全屏） |
| `/accounts` | AccountList | 账户 | 账户管理 |
| `/accounts/:id/edit` | AccountEdit | — | 账户编辑（保留） |
| `/reports` | ReportsPage | 报表 | 占位页 |
| `/me` | MePage | 我的 | 占位页 |

旧路由处理：
- `/transactions` → 重定向到 `/`
- `/settings` → 保留路由，但不在 Tab 栏中，后续从"我的"页面进入

## 二、底部 Tab 导航

```
[首页 (Home)]  [报表 (BarChart3)]  [账户 (Wallet)]  [我的 (User)]
```

- `/` → 首页高亮；`/record`、`/record/:id` → 不高亮任何 tab
- `/accounts` → 账户高亮；`/accounts/:id`、`/accounts/:id/edit` → 账户高亮
- `/reports` → 报表高亮
- `/me` → 我的高亮
- 记账页（`/record`、`/record/:id`）、筛选页（`/filter`）不显示 Tab 栏

## 三、各页面设计

### 3.1 TransactionList（流水首页 / 账户详情）

两种模式，由路由参数决定：

**首页模式 (`/`)：**
```
┌─────────────────────────────────┐
│  🔽 我的账本          🔍 筛选   │  ← Header：左侧账本切换预留，右侧筛选图标
├─────────────────────────────────┤
│  净资产 ¥12,350.00              │
│  资产 ¥15,000  负债 -¥2,650     │  ← 汇总（根据筛选动态计算）
├─────────────────────────────────┤
│  6月10日 周三                    │
│  🍜 餐饮    招行卡    -¥32.50   │
│  💰 工资    招行卡   +¥8,000    │
│  ...                            │  ← 按日期分组流水列表
└─────────────────────────────────┘
                          ┌───┐
                          │ + │  ← FAB：position: fixed, top: 75%, right: 16px
                          └───┘  圆形，阴影，点击 → /record
```

**账户详情模式 (`/accounts/:id`)：**
- Header：左侧为账户名 + 颜色圆点（从 accountStore 查找），右侧筛选图标
- 汇总卡片显示三行：
  - 当前余额：该账户 `current_balance`（从 accountStore 取）
  - 收入合计：筛选范围内该账户的收入总额
  - 支出合计：筛选范围内该账户的支出总额
- 流水列表：默认筛选当前账户（只显示该账户为 from 或 to 的交易）
- FAB → `/record?account=:id`，RecordPage 读取 query 默认选中该账户
- 右上角筛选按钮可叠加额外筛选条件（日期范围、标签）

**汇总计算方式：**
- 首页模式：前端从筛选后交易聚合 `净收支 = totalIncome - totalExpense`，不涉及 accountStore 余额（因为是多账户混合）
- 账户详情模式：余额从 accountStore 取；收入/支出从筛选后交易中只取涉及该账户的部分聚合
- 两种模式都随筛选条件变化动态更新

### 3.2 RecordPage（记账表单）

```
┌─────────────────────────────────┐
│  ← 记账                         │
├─────────────────────────────────┤
│  [支出]  [收入]  [转账]           │  ← 类型切换
├─────────────────────────────────┤
│  金额                            │
│  ┌─────────────────────────────┐ │
│  │ ¥ 100+50                    │ │  ← 表达式输入，右侧显示实时求值结果
│  │       = 150.00              │ │
│  └─────────────────────────────┘ │
├─────────────────────────────────┤
│  🍜  🚌  🛒  🎮                  │  ← 分类网格（默认选中第一个）
│  🏠  📱  💊  💸                  │
├─────────────────────────────────┤
│  扣款账户                        │
│  [招行卡 ● ▽]                    │  ← 点击弹出 AccountPickerSheet
├─────────────────────────────────┤
│  日期时间                        │
│  [2026-06-10 12:30       ▽]     │  ← 点击弹出 DateTimeSheet
├─────────────────────────────────┤
│  🏷️ 标签                         │
│  [+ 添加标签]                     │
├─────────────────────────────────┤
│  ┌───┬───┬───┬──────────┐       │
│  │ 7 │ 8 │ 9 │ 再记一笔   │       │
│  ├───┼───┼───┼──────────┤       │  ← 自定义键盘，永远可见
│  │ 4 │ 5 │ 6 │    +     │       │
│  ├───┼───┼───┼──────────┤       │
│  │ 1 │ 2 │ 3 │    -     │       │
│  ├───┼───┼───┼──────────┤       │
│  │ . │ 0 │ ⌫ │   完成    │       │
│  └───┴───┴───┴──────────┘       │
└─────────────────────────────────┘
```

**交互细节：**

- **字段顺序**：类型 → 金额 → 分类 → 账户 → 日期时间 → 标签
- **分类默认值**：切换类型时自动选中该类型第一个分类（sort_order 最小的），支出默认"餐饮"，收入默认"工资"
- **金额输入**：自定义键盘输入为计算表达式，支持 `+` `-` 运算符和小数点。金额输入框中显示表达式原文，旁边或下方显示实时计算结果。非法表达式（以运算符结尾、表达式为空、计算结果 ≤0 或非数字）时"完成"和"再记一笔"按钮置灰
- **键盘永远弹出**：页面进入时金额 input 自动 focus，键盘始终显示不隐藏
- **"完成"按钮**：表达式合法时可用。保存交易并导航到首页 `/`
- **"再记一笔"按钮**：表达式合法时可用。保存交易后留在当前页，重置：清空金额、分类恢复到默认值、日期时间刷新为当前、保留账户选择、保留标签选择
- **日期时间**：点击日期时间区域 → 弹出 DateTimeSheet（底部弹出面板式）
- **"记一笔"（保存）按钮已移除**，功能由键盘"完成"/"再记一笔"替代
- **记账页不显示底部 Tab 栏**

│  ← 筛选                         │
├─────────────────────────────────┤
│  📋 账户                         │
│  [全部账户 ▽]                    │  ← 点击弹出 AccountPickerSheet
├─────────────────────────────────┤
│  📅 日期范围                      │
│  [2026-06-01] ─ [2026-06-10]    │  ← 点击分别弹出日期面板
├─────────────────────────────────┤
│  🏷️ 标签                         │
│  [☐ 午餐] [☑ 工作日] [☐ 外卖]    │  ← 多选标签，从 tagStore 加载
├─────────────────────────────────┤
│                                 │
│  [      应用筛选      ]          │  ← 确认，筛选参数写入 route query/composable

- 三个维度 AND 逻辑
- 筛选状态通过 route query 传递回 TransactionList
- TransactionList 读取筛选参数，传入 SQL WHERE 条件重新 fetch

## 五、数据流

```
FilterPage → route query (account, dateFrom, dateTo, tags)
    ↓
TransactionList 读取 query → transactionStore.fetchAll(ledgerId, filters)
    ↓
transactionStore 前端计算 filteredIncome / filteredExpense / netChange
    ↓
首页/账户详情页汇总卡片动态渲染
    ↓
AccountStore 在交易 CRUD 后刷新（保持账户余额准确）
```

- 筛选条件直接作为 SQL WHERE 参数，减少前端筛选量
- 汇总计算在前端基于已加载的 transactions 做 computed

## 六、路由守卫

- `/transactions` → 301 redirect 到 `/`
- 记账页和筛选页不渲染底部 Tab 栏 → 通过 `meta: { hideTab: true }` 控制
